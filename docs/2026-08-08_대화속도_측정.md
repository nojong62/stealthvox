## 1. 유저 쪽 통신 로직 (3모드 공통)

```

   ↓

   ↓

   ↓

   ↓
통과 → 그대로 둠
```

## 3. TTS 2.1초는 앱에서 못 줄인다

문장 길이와 무관하게 고정이다.

| 글자수 | TTS 왕복 |
|---|---|
| 20 | 2814ms |
| 22 | 1861ms |
| 36 | 1739ms |
| 47 | 2445ms |
| 54 | 2356ms |
| 74 | 2294ms |
| 87 | 2251ms |
| 92 | 2750ms |

**20자가 2814ms, 92자가 2750ms.** 상관이 없다.

- TLS/커넥션 문제 아님 — 같은 풀을 쓰는 전사가 2초 전에 0.9초로 끝난다
- 요청 자체는 정상 — `tts-1` + `response_format: pcm` 스트리밍
- 첫 바이트 도착 후 재생까지는 0.26초뿐

→ **서버가 첫 오디오를 내놓기까지의 시간이다.** 짧게 잘라도 안 줄어든다.
   그래서 "문장 단위 청킹으로 TTS를 줄인다"는 제안은 철회했다.

## 4. 두 귀 불일치 — 관찰 중

`[STT-RAW]`에 `dg=`(버리는 Deepgram 전사)를 같이 남기면서 보이기 시작했다.

| transcribe | Deepgram | 판단 |
|---|---|---|
| "2층 별로던데?" | "이 책 별로던데?" | Deepgram 맞음 |
| "트리거나기 전에" | "소리가 나기 전에" | Deepgram이 맞아 보임 |
| "앞선으로 할 거예요" | "앞산으로 할까요?" | Deepgram이 맞아 보임 |
| "필요하면 연락할게요" | "필요하면 부탁할게요" | 어느 쪽이 맞는지 모름 |

**확실한 건 2~3건이다.** transcribe가 맞고 Deepgram이 틀린 경우를 못 알아봤을
수 있어 표본이 한쪽으로 기울었을 가능성이 있다. **며칠 더 모은 뒤 판단한다.**

> 참고 — "미니가 고치게 하자"는 권하지 않는다. 고치면 유저가 안 한 말이 조용히
> 들어간다. 대신 **두 전사를 미니에게 같이 주고 고르게 하는 것**이 안전하다.
> 지어내는 게 아니라 실제로 들린 둘 중 선택이고, Deepgram 전사는 이미 만들어
> 버리는 중이라 비용이 0이다.

## 5. 써클톡 vs 시나리오톡

| | 써클톡 | 시나리오톡 |
|---|---|---|
| TTS 엔진 | `TtsAdapter` (공유 서비스) | `TtsQueueManager` (roleplay 내부) |
| 재생 방식 | PCM 스트리밍 + preroll | 문장 단위 청크 |
| 프리페치 | 있음 (미사용) | 없음 |
| 계측 로그 | 풍부 | 거의 없음 |
| 스트리밍 생성 | 있음 (죽은 코드) | 있음 (옛 영어용, 재사용 불가) |
| 되묻기 2차 관문 | 없음 | 있음 |

측정 가능한 구간은 사실상 같다 — 전사 901 vs 889ms, 게이트 825 vs 992ms.
**시나리오톡은 재생 시작 시각을 안 찍어서 핵심 비교가 불가능하다.**

### 한 줄 요약

**써클톡은 장비가 좋은데 안 쓰고, 시나리오톡은 장비가 낡았는데 쓰고 있다.**

- 써클톡 — 프리페치·스트리밍·계측이 다 있는데 좋은 건 전부 죽은 코드
  (`_processRelayPipeline`, `// ignore: unused_element`)에 갇혀 있다.
- 시나리오톡 — 엔진은 구식이지만 **오프너**에서 스트리밍+문장 단위 발사가
  실제로 돈다. 단 **라이브 턴(매 턴)은 통문장**이다.

### 다음에 할 일의 크기

| | 규모 | 범위 | 되돌리기 |
|---|---|---|---|
| ① 써클톡 장비 켜기 | 중간 | 라이브 턴 하나 | 쉬움 |
| ② 시나리오톡 엔진 교체 | 큼 | 음성 경로 11곳 동시 | 어려움 |

**①을 먼저 하고 ②는 그 결과를 보고 정한다.** ①이 되면 써클톡이
"빠른 경로 + 좋은 엔진 + 계측 완비"가 되고, 그때 시나리오톡을 맞추면 목표가
분명해진다. ②를 먼저 하면 낡은 배관을 새 엔진에 붙이는 것이라 속도 이득이
없을 수 있다.

## 6. 스트리밍을 오늘 안 넣은 이유

라이브 턴 응답은 프롬프트상 **최대 2문장, 문장당 15단어 이하**다(실측 45~92자).

쪼개면 조각이 2개뿐인데 두 번째 조각이 TTS 2.3초를 다시 기다린다. 첫 조각
오디오가 2초 안팎이라 **그 사이에 말이 끊길 수 있다.** 오프너는 문장이 길어
안 끊기지만 라이브 턴은 짧아서 위험하다.

그리고 시나리오톡의 `streamRoleplayResponse`는 **옛 영어 파이프라인용**이라
시그니처가 달라 그대로 못 쓴다. 한국어용 스트리밍 함수를 새로 써야 한다.

→ **0.8초를 더 벌자고 대화가 끊기면 손해다.** 넣으려면 실기기에서 끊김 여부를
   먼저 확인해야 한다.
