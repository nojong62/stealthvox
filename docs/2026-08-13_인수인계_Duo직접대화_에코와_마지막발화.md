```

URL      https://duo-relay-450483026108.asia-northeast3.run.app
리전     asia-northeast3

기타     --timeout 3600 --concurrency 250 --allow-unauthenticated
런타임 SA 450483026108-compute@developer.gserviceaccount.com (roles/editor)
```

**`--max-instances 1`을 절대 올리지 말 것.** 방 정보가 인스턴스 메모리에만 있어서
2대가 되면 호스트와 게스트가 서로 다른 인스턴스에 붙고 **소리가 조용히 안 건너간다.**
동시 통화가 늘어 한 대로 못 버티는 시점이 오면 방 단위 라우팅(Redis pub/sub 또는
room→instance 고정)을 먼저 붙여야 한다.

`VERIFY_ROOM`은 환경변수를 안 넣었으므로 **기본값 1**이다. Firestore `duo_sessions`를
직접 읽어 uid가 그 방의 hostUid/partnerUid인지 검증한다. 런타임 SA가 `roles/editor`라
권한은 이미 있고, 실접속에서 `verify_failed` 없이 통과하는 것을 확인했다.

`--min-instances 1`은 **상시 과금**이다. 테스트가 뜸한 기간에는 0으로 낮춰도 되지만
첫 연결이 콜드스타트만큼 느려진다.

## §3 이번에 고친 것

### (1) 에코·"쉐" 잡음 — AEC와 통화 모드

원인은 둘이 맞물린 것이었다.

| 위치 | 문제 | 조치 |
| --- | --- | --- |
| `MainActivity.kt` | AudioTrack이 `USAGE_MEDIA` → 미디어 스피커로 나가고 AEC 참조 신호가 없음 | `start`에 `voiceCall` 인자 추가. true면 `USAGE_VOICE_COMMUNICATION` + `MODE_IN_COMMUNICATION` + 스피커폰 유지, 종료 시 원래 상태로 복원 |
| `AnyonePreparedAudioCapture` | `echoCancel`/`noiseSuppress` 없음 | 파라미터로 받도록. **기본값 false — Circle Talk 무변경** |
| `routine_mode_duo.dart` | 위 설정을 안 씀 | 직접 대화만 둘 다 `true` |

**`AnyonePreparedAudioCapture`의 기본값을 바꾸지 말 것.** Circle Talk은
`echoCancel`이 켜지면 AI 목소리가 나가는 동안 유저 입력까지 눌려 빈 전사만 돌아온다
(같은 파일 ECHO-GUARD 주석 참고). 같은 채널 `stealthvox/realtime_pcm`을 쓰는
첫 턴 Realtime 음성도 `voiceCall` 인자를 안 보내므로 미디어 재생 그대로다.

### (2) 통화 종료 시 마지막 발화 누락 ★

**로그로 확인된 실제 결함이었다.**

```
02:41:56.926 speech_started → 02:41:58.852 speech_stopped → completed seq=10  ✅
02:42:05.413 speech_started → (말하는 중)
02:42:07.518 GATE close reason=user_tap, dispose
             ← 이 발화의 completed 없음. 문장이 사라졌다.
```

원인: `_stopDirectCall()`이 **맨 먼저 `++_directGeneration`**을 올렸다.
`onTranscriptCompleted`는 세대가 어긋나면 즉시 리턴하므로, 전사문이 도착해도
버려졌다. 게다가 기다리지도 않고 바로 `dispose()` 했다.

**바뀐 종료 순서**

```
① 캡처 구독 취소 + 녹음 정지          (추가 PCM 차단)
② flushPendingUtterance()             (마지막 버퍼 확정 → 전사문 최대 2초 대기)
③ _awaitDirectSaves()                 (History·상대 채널 저장 완료까지, 상한 3초)
④ ++_directGeneration → dispose       (여기서야 세대를 올린다)
```

`openai_streaming_transcribe_session.dart`에 붙은 것:

- 진행 중 발화 추적 — `speech_started` → 말하는 중, `committed` → item 대기 등록,
  `completed`/`failed` → 해제. `hasPendingUtterance`로 노출
- `flushPendingUtterance({reason, timeout: 2초})`
  - **게이트를 먼저 닫는다.** 열어 둔 채 commit하면 확정 직후 들어온 PCM이 새 발화를 연다
  - 진행 중 발화가 없으면 즉시 false — 말 안 하고 끄면 안 느려진다
  - 아직 `committed` 전일 때만 `input_audio_buffer.commit` 전송.
    이미 확정된 발화에 또 commit하면 빈 버퍼 error만 난다
  - flush 중 `error`·`failed`·`dispose`에서도 대기를 풀어 상한까지 노는 일이 없다

`routine_mode_duo.dart`에 붙은 것:

- `_canSaveDirectTranscript()` — flush 창 안이면 저장 허용. **`mounted`는 안 본다**
  (저장은 Firestore 쓰기뿐인데 그 조건을 걸면 마지막 문장을 또 잃는다)
- `_uploadMyMessage`도 `await` — 안 하면 마지막 문장이 내 History에만 남고
  상대 History엔 안 간다
- 중복 종료 가드 `_directStopping`, 중복 저장 가드 `_savedDirectItemIds`
- 실패 시 경고 로그 두 종류 (원인이 갈린다)
  - `⚠️ last_utterance_lost` — 전사문 자체가 상한 내 미도착. **어디에도 저장 안 됨**
  - `⚠️ save_wait_timeout` — 전사문은 왔는데 Firestore 쓰기가 상한 초과

> **`input_audio_buffer.commit`은 server_vad 모드에서도 받는다.** 파일 상단 주석의
> "앱에서 commit하지 않는다"는 평상시 이야기고, 종료 flush에서는 쓴다.

### (3) 게스트 입장 언어

오버레이가 화면에만 기본값을 보여 주고 `FFAppState`에는 옛 값이 남던 어긋남을 없앴다.
`_normalizeGuestLangs()` — 저장된 값이 목록(12개 언어)에 있으면 **그대로 두고**,
비었거나 목록 밖일 때만 `ORIGIN=Korean` / `TARGET=English`. 오버레이 열 때와
"입장하기" 누를 때 양쪽에서 확정한다. 검증용 `[GUEST-LANG]` 로그 추가.

## §4 실측으로 확인된 사실

### 릴레이 통신은 깨끗하다

```
room W488gdva5aTVib3jv4JU, 44초
릴레이 HOST  in=2050560 out=2100480
       GUEST in=2100480 out=2050560     ← 완전 대칭, 유실·복제 0
호스트 sent=2050560 recv=2100480 played=2081280 droppedBytes=0
RTT    로컬 릴레이 5~7ms / Cloud Run 13~14ms
```

에코는 네트워크가 아니라 **스피커→마이크 음향 되먹임**이다. 볼륨을 낮추면
울림이 줄어드는 것으로 확인했다(네트워크 원인이면 볼륨과 무관해야 한다).
기기 로그에도 `AudioFlinger: g_hw_speaker_amp_temp_spk` — 외부 스피커가 계속 돌았다.

### 직접 대화는 PTT가 아니다

`_onDirectMicToggle` → `_startDirectCall()`은 **로컬 탭에서만** 호출된다.
호스트가 눌러도 게스트 마이크는 안 열린다. **각자 자기 폰에서 눌러야** `peers=2`가
되고, 그때부터 서로 끼어들며 말할 수 있다(full duplex). 한 번 누르면 계속 열려 있다.

상대가 없으면 내 PCM은 그냥 버려진다(`droppedNoPartner`).

### 화자별 전사는 이미 구현돼 있다

각 폰이 **자기 마이크만** 전사한다. 서버가 섞인 음성에서 화자를 추정하는 일이 없다.

| 단계 | 코드 |
| --- | --- |
| 내 발화 | `_handleDirectTranscript` → `speaker_uid=내 uid`, `speaker_seq`, `spoken_at_ms`, `source_lang` |
| 상대 발화 | `_handleIncomingMessage` 직접 모드 분기 → `speaker_uid=senderUid`, 상대 seq/spokenAt/srcLang |
| 정렬 | 응답 도착순이 아니라 **말을 시작한 시각**(`onSpeechStarted`) 기준 |

`role` 필드의 `HOST`/`SYSTEM`은 **화자 신원이 아니라 "그 폰 기준 내 것 / 상대 것"**이다.
게스트 폰에서는 게스트 자기 말이 `HOST`로 저장된다. 신원은 `speaker_uid`에 있다.

### 전사는 VAD로 잘라 보내지 않는다

게이트가 열린 동안 PCM이 **계속** 올라간다(44초 통화 → `sentAudioMs=42720`).
서버 VAD는 발화 경계만 판정한다. 따라서 전사 비용은 발화 시간이 아니라
**통화 시간에 비례**하고, 두 폰이 각자 보내므로 1시간 통화면 2시간분이다.
(중복 전사가 아니라 각자 자기 몫이다.) 비용 최적화는 별건으로 다룬다.

### 내부 테스트 86에 이미 직접 대화가 있다

git 커밋 타임라인상 직접 대화는 87 코드로 보이지만, 실제 배포된 86에 들어 있다.
2026-08-13 새벽 검증을 전부 이 86 빌드로 했다.
**86 = 직접 대화 있음 / AEC·마지막 발화 수정 없음. 87 = 그 둘 추가.**

## §5 87에서 반드시 확인할 것

### 종료 4시나리오 (호스트 폰 로그)

| 시나리오 | 기대 |
| --- | --- |
| 말하는 도중 끄기 | `[STREAM-FLUSH] commit` → `transcription_completed` → `completed seq=N` → `drained=true` → 그 뒤에 dispose |
| 발화 완료 직후 끄기 | flush 대기 없음 (`waitedMs` ≈ 0) |
| 말 안 하고 끄기 | `[STREAM-FLUSH]` 로그 자체가 없음 = 즉시 종료 |
| 연속 두 번 끄기 | 두 번째 탭이 `_directStopping`에 막혀 종료가 한 번만 |

`⚠️ last_utterance_lost` / `⚠️ save_wait_timeout`이 뜨면 그 문장은 저장 안 된 것이다.

### 양쪽 History (게스트 폰 필요)

`completed`가 왔다고 Firestore 저장까지 끝난 게 아니다. 그래서 `_awaitDirectSaves()`가 있다.
**내 폰뿐 아니라 상대 폰 History에도 마지막 문장이 남는지 반드시 확인할 것.**

### 에코 (AEC 적용 후)

- 상대 발화가 내 발화로 **중복 저장**되지 않는가 — 에코가 내 마이크 전사에 잡히면
  상대 말이 내 `HOST` 줄로도 저장된다. `_isNoiseTranscript`는 노이즈용이라 이걸 못 거른다
- 동시에 말했을 때 화자가 뒤바뀌지 않는가 (구조상 안전하지만 확인)
- "쉐" 잡음이 `noiseSuppress`로 줄었는가

- **방이 안 닫힌다.** `isDuoEnabled`를 false로 되돌리는 코드가 없다. 생성 시 false →
  초대 시 true, 그게 끝. 덕분에 게스트가 설치에 오래 걸려도 초대가 안 죽지만,
  몇 주 전 링크도 계속 유효하다. 지금은 테스트에 유리해 그대로 뒀다.
- **`test/widget_test.dart`가 깨져 있다.** `flutter create` 기본 스켈레톤이
  `MyApp()`을 그냥 pump해서 `FirebaseException`이 난다. 원래부터 깨진 파일이라
  손대지 않았다. 지우거나 Firebase 목킹을 붙이는 건 별건.
- **전사 비용 최적화** — 게이트를 발화 구간에만 여는 작업. 87 범위 밖.
