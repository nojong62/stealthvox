# StealthVox 앱 테스트 자동화 방법 정리

> 작성: 2026-07-16 · 폰(Galaxy S25 / SM-S931N, Android 16) USB 연결 상태에서 검토
> 목적: 매번 사람이 직접 말하고 버튼을 누르지 않고, PC(Claude)에서 앱 실행 시나리오를 반복 점검하는 방법 정리

---

## 1. 배경 — Anyone 모드의 실제 데이터 흐름

```
🎤 마이크 → Deepgram(STT) → 확정 텍스트 → GPT → TTS(음성 응답)
         └─────── "음성 입력" 구간 ───────┘
```

관련 로그 마커:
```
🔀 [COMMIT-01] 확정: "오늘은 학교에서..." → 파이프라인 시작
🔀 [COMMIT-03] _processRelayPipeline 호출
```

- 앱 코드 위치: `lib/custom_code/widgets/routine_mode_anyone.dart`
- 마이크 캡처 설정(`RecordConfig`, 2551줄 부근): `pcm16bits, 16kHz, 1ch`, **에코 캔슬/노이즈 억제 설정 없음** → 자기재생 트릭(아래 ②)이 가능한 근거.

---

## 2. 핵심 제약

- **실물 폰 마이크에 오디오 직접 주입 = 불가능.** adb에 가상 마이크가 없고, 앱에 텍스트로 파이프라인을 우회하는 입구도 없음. (루팅/오디오 루프백 장비 없이는 안 됨)
- 따라서 "Claude가 대신 말하기"는 아래 우회 기법으로만 가능.

---

## 3. 3가지 기법과 역할

```
① UI 자동화 (adb input tap/text)  ← 버튼·네비게이션 (모든 방식의 공통 뼈대)
② 스피커 자기재생                  ┐  둘 다 "사용자 발화"를 만들지만
③ 디버그 주입 (코드+게이트)        ┘  통과하는 코드 계층이 다름
```

- **①은 공통 기반**, **②·③은 "말하기" 단계를 대체하는 서로 다른 두 방법**.
  - **② 자기재생** → 마이크를 **통과**함 (실제 오디오 → Deepgram)
  - **③ 디버그 주입** → 마이크를 **우회**함 (확정 텍스트를 파이프라인에 직접 주입)

### ① UI 자동화 (`adb shell input`)
버튼 탭, 다이얼로그, 로그인 폼 입력, 화면 전환 등을 좌표/키 이벤트로 자동 실행. 말하는 순간만 빼면 전부 자동화 가능.

### ② 스피커 자기재생
앱 마이크에 에코 캔슬이 꺼져 있어, 폰 스피커로 사람 음성 WAV를 틀면 그 소리를 자기 마이크가 다시 잡아 Deepgram이 인식.
- 절차: 짧은 영어 문장 WAV 1개 준비(예: *"Hello, how are you today?"*) → 폰에 넣고 → 필요할 때마다 스피커로 재생.
- 실제 마이크+Deepgram 경로를 그대로 통과하므로 **데드마이크 검증에도 유효**.
- ⚠️ 인식률이 스피커 볼륨/주변 소음에 의존(flaky). 조용한 환경 + 볼륨 최대에서 잘 됨.

### ③ 디버그 주입 (코드 수정 필요)
마이크와 Deepgram을 건너뛰고 "확정 텍스트"를 코드로 직접 밀어넣는 숨겨진 개발자용 입구.
- 예: 숨겨진 롱프레스 버튼, 또는 `adb shell am broadcast -a ...DEBUG_INJECT --es text "..."` 인텐트로 `_processRelayPipeline("...")` 호출.
- **반드시 `kDebugMode` 등으로 게이트**하여 실 사용자 빌드에 나가지 않게 해야 함.

---

## 4. 커버리지 비교

| 기법 | 코드수정 | 🎤 마이크/STT 검증 | STT 이후(GPT·TTS·전환·저장) | 안정성 |
|---|:---:|:---:|:---:|:---:|
| ① UI 자동화 | ✕ | — (버튼만) | — (버튼만) | 높음 |
| ② 자기재생 | ✕ | ✅ | ✅ | 중간(환경 의존) |
| ③ 디버그 주입 | ✅(게이트) | ❌ | ✅ | 매우 높음 |

### 조합
- **①+② (핸즈프리 + 마이크 포함 전체)** → **1순위 데드마이크 검증 가능**. 단 flaky.
- **①+③ (핸즈프리 + STT 이후만)** → 1순위는 못 보지만 **무인·결정적·무한 반복** 가능.

---

## 5. 둘 다(②와 ③) 하면 더 좋은 이유

1. **커버리지가 상보적** — ②는 마이크 계층, ③은 그 이후 계층. 합치면 전 구간을 덮음.
2. **진단 계층 분리 (가장 큰 이득)** — 예: "AI 응답이 안 나온다" 증상 발생 시
   - ③(주입)으로 재현되면 → 문제는 **GPT/TTS 파이프라인**
   - ③에선 멀쩡, ②(음성)에서만 실패 → 문제는 **마이크/Deepgram STT**
   - ③이 "마이크"라는 불안정 변수를 제거 → **실패 원인 계층을 즉시 분리**.

---

## 6. 권장 세팅 및 진행 순서

1. **① 항상 켜기** (버튼 자동화)
2. **③ 디버그 주입 추가** (`kDebugMode` 게이트, 별도 브랜치) → 2·3·4순위(TTS·전환·저장·가입)를 무인 반복 점검
3. **② 자기재생 준비** (음성 클립 1개) → 1순위 데드마이크처럼 **마이크 계층만** 콕 검증

> 요약: **③ = 빠르고 안정적인 주력, ② = 마이크 전용 보조.**

## 부록 A. 1순위(콜드스타트 데드마이크) 테스트 결과 — 2026-07-16

**결과: ✅ 데드마이크 재현 안 됨 (수정 정상 작동)** — 단, 마이크 권한이 이미 허용된 조건.

콜드스타트 타임라인:
```
08:10:43.015  체험 버튼 탭
08:10:46.171  🔑 KEY-READY  deepgram=true openAi=true   (탭 후 3.2초)
08:10:46.255  🎤 LISTEN-01 → LISTEN-04 → LISTEN-05 connectAndStart 완료
08:10:55.645  🔀 첫 발화 인식됨: "오늘은 학교에서 문제가..."   ← 마이크 정상
```
`START-GATE 보류`도, 재시도 초과도 없었음. 첫 진입에서 마이크 즉시 연결, 첫 발화 정상 인식.

### 같은 로그에서 발견된 다른 이슈 2건
- **🐞 A. `PIPE-ERR` defunct 크래시** (`08:11:50`)
  - `'_lifecycleState != _ElementLifecycle.defunct' is not true` → 이어서 `⚠️ [PIPE-NORESTART] 마이크 재시작 조건 불충족`.
  - 트라이얼 60초 만료(`_handleTrialEnd`) teardown과 3번째 턴 파이프라인이 겹쳐 발생. 이번엔 무해했으나, 정식 모드에서 턴 도중 이 크래시가 나면 마이크가 죽은 채 방치될 수 있는 패턴.
- **🐞 B. Firestore `permission-denied`** (`08:11:09`)
  - `SAVE-05`(sessions.add) 성공 후, `users/{uid}.update({'total_sessions'})`(SAVE-06)에서 거부.
  - 하위 컬렉션 쓰기는 되는데 부모 문서 필드 업데이트만 보안 규칙에서 막힘. 대화 자체는 저장되나 세션 카운터 미증가. 정식 유저와 공유되는 경로라 규칙 확인 필요.

### 미검증(다음 단계)
- 권한 회수 상태의 콜드스타트(=권한 팝업이 시작 중 뜨는 진짜 데드마이크 조건)는 아직 미검증.
  - 참고: 정식 로그인 + `trialCompleted=true` 상태라 인트로가 Auth 화면으로 떠서 체험 버튼이 안 나옴. 재현하려면 로비 → ENTER → Anyone 경로(계정 유지) 또는 `pm clear`(재로그인 필요) 필요.

## 부록 B. 로그 캡처 참고

adb 경로: `C:\Users\u\AppData\Local\Android\Sdk\platform-tools\adb.exe`

필터 예시:
```bash
adb logcat -c && adb logcat | grep -E "TrialDebug|KEY-|START-GATE|LISTEN-|COMMIT-|PIPE-|SAVE-|HIST-"
```

주요 마커:
- `[TrialDebug]` — 인트로/체험 진입
- `🔑 [KEY-READY]` — Deepgram/OpenAI 키 준비
- `🎤 [START-GATE]` — 시작 보류(키 or 마이크 권한 미준비 = 데드마이크 후보)
- `🎤 [MIC-06] startStream 성공` / `❌ [MIC-ERR-C]` — 마이크 스트림 시작/실패
- `✅ [LISTEN-02] onConnected` — Deepgram 연결 성공(마이크 정상 신호)
- `🔀 [COMMIT-01]` — 발화 확정 → 파이프라인 시작
- `🧠 [PIPE-01..10]` — GPT/TTS 파이프라인 단계
- `❌ [PIPE-ERR]` / `⚠️ [PIPE-NORESTART]` — 파이프라인 크래시/마이크 미재시작
