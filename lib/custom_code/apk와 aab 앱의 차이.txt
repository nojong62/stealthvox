네. **APK로 설치한 앱에서도 회원가입(Login/Register)은 가능합니다.**
하지만 **결제 관련 기능은 제한**이 있습니다.

정리하면:

| 기능                       | APK 직접 설치 (Debug/Release APK) | Google Play 내부 테스트 앱 |
| ------------------------ | ----------------------------- | -------------------- |
| 회원가입 (Firebase Auth)     | ✅ 가능                          | ✅ 가능                 |
| 로그인                      | ✅ 가능                          | ✅ 가능                 |
| Firestore 데이터 저장         | ✅ 가능                          | ✅ 가능                 |
| 대화 기능 (Duo, Roleplay 등)  | ✅ 가능                          | ✅ 가능                 |
| 관리자 시간 부여 (Firestore 수정) | ✅ 가능                          | ✅ 가능                 |
| RevenueCat 시간 차감 로직      | ✅ 가능                          | ✅ 가능                 |
| Google Play 인앱결제(IAP) 구매 | ❌ 불가능                         | ✅ 가능                 |
| 구독/시간권 구매 테스트            | ❌ 불가능                         | ✅ 가능                 |
| 실제 결제 카드 테스트             | ❌ 불가능                         | ✅ 가능                 |

### 중요한 점

#### 1. 회원가입

현재 StealthVox 구조상 Firebase Authentication을 사용하므로:

* APK 설치
* 이메일 회원가입
* Firebase users 생성
* Firestore users 문서 생성

→ 모두 정상 작동합니다.

---

#### 2. 시간 차감

이미 `remaining_seconds` 가 있는 사용자라면:

* Duo 사용
* Roleplay 사용
* History 사용

시 **시간 차감 로직은 APK에서도 정상 작동**합니다.

즉:

* 관리자가 Firebase에서 1시간 지급
* APK 설치 사용자 사용

→ 시간 감소 테스트 가능.

---

#### 3. 결제

여기서 차이가 납니다.

APK로 직접 설치하면:

* Google Play Billing 연결 안 됨
* RevenueCat도 실제 상품 조회 실패
* 구매 버튼 누르면 오류 발생 가능

즉:

> **구매 기능 테스트는 반드시 Google Play 내부 테스트 트랙으로 설치해야 합니다.**

---

### 실제 개발 시 추천

**APK 테스트**

* 회원가입
* 로그인
* AI 대화
* 시간 차감
* Firebase 저장
* 히스토리 저장

**Play Console 내부 테스트**

* 인앱결제
* RevenueCat
* 테스트 카드 결제
* 구독 상품 노출 확인

---

그래서 지금 StealthVox 개발 단계에서는:

1. **일반 기능 검증 → APK 사용**
2. **결제 검증 → Play 내부 테스트 사용**

이렇게 병행하는 것이 가장 효율적입니다.

특히 지금처럼 **Google 내부 테스트 배포가 늦거나 검은 화면 문제가 있을 때는 APK로 대부분의 기능을 먼저 검증하는 것이 좋습니다.** 결제 부분만 마지막에 Play 테스트로 확인하면 됩니다.
